# Per-project working directories

Hermes mounts `$ASSISTANT_DATA_ROOT/projects/` at `/opt/projects`. Each
**immediate subdirectory** is a discoverable Project: source notes and agent
drafts side by side. Default root is `./data`; relocate with
[User data directory](data-dir.md).

This page is the **convention** for getting more reliable answers from smaller
local models without stuffing every project into LightRAG.

## Three layers

| Layer | Role |
|---|---|
| **FS library** | Immediate children of `projects/` (container: `/opt/projects/<slug>`). Source of truth for *existence*. Plain folders count — `AGENTS.md` is optional. |
| **`projects.db` metadata** | Optional name, color, archive, multi-folder membership, `active_id`. Attaches when a row’s path matches a library folder. Not required before the agent can read/write the mount. |
| **Git `discover_repos`** | Orthogonal desktop/repo scan (`.git` roots). Must not be the only way projects appear. |

`make project-init` and plain `mkdir` under the projects root both show up via the
same discovery. Dropping or creating a folder on the host is enough; no separate
`projects.create` fiction for library membership.

Clients that call Hermes `projects.list` / `projects.tree` (e.g. Boundary /
`hermes serve`) and the WebUI workspace dropdown both merge the FS library on
read. Selecting a synthetic library project via `projects.set_active` may lazily
insert a DB row so `active_id` stays stable.

## Quick path

```bash
# From the assistant repo root
make project-init PROJECT=my-project
# Or: mkdir -p "$ASSISTANT_DATA_ROOT/projects/my-project"
# Edit $ASSISTANT_DATA_ROOT/projects/my-project/AGENTS.md
# Add source markdown under notes/ (optional description: frontmatter)
# Optional: list extra host dirs in sources.yaml, then:
#   make context-root-add DIR=/absolute/path/to/notes
make project-index PROJECT=my-project
```

In Hermes WebUI, select the workspace `/opt/projects/my-project` (it appears
automatically). Manually adding a workspace is only needed for paths **outside**
the shared library root.

## What each file is for

| Path | Role |
|---|---|
| `AGENTS.md` | Short brief (aim for ~1.5–2k tokens). Injected on WebUI turns while this workspace is selected. |
| `sources.yaml` | Hand-edited extra directories to index. Missing file = walk this project only. |
| `INDEX.md` | One-line map of source files. Regenerated by `make project-index`. |
| `.index-manifest.json` | Content hashes for staleness checks. Do not hand-edit. |
| Source `*.md` / `*.txt` | Prefer a YAML `description:` for INDEX quality; otherwise the first `#` heading is used. |
| `notes/` vs `drafts/` | Keep material you wrote apart from agent output. |

The indexer skips `AGENTS.md`, `INDEX.md`, `README.md`, `sources.yaml`, hidden
directories, and anything under `templates/`, `applications/`, `artifacts/`, or
`drafts/`.

## Extra source directories

`INDEX.md` is generated. Declare extra trees in `sources.yaml` (copied by
`make project-init`):

```yaml
version: 1
sources:
  - id: project
    path: .
    retrieval: files
    include: ["**/*.md", "**/*.txt"]
  - id: notes-vault
    path: /Users/you/Notes/this-project
    retrieval: files
    include: ["**/*.md"]
```

Path rules in the generated INDEX:

- Files under the project stay **relative** (`notes/resume.md`). Hermes opens
  them under `/opt/projects/<slug>/`.
- Files in extra host dirs are **host-absolute**. Those dirs must be bind-mounted
  into Hermes at the **same path**, read-only:

```bash
make context-root-add DIR=/Users/you/Notes/this-project
docker compose up -d --force-recreate hermes-worker
# recreate hermes instead when HERMES_TERMINAL_BACKEND=local
make project-index PROJECT=my-project
```

Do not use `$ASSISTANT_DATA_ROOT/projects/...` in `sources.yaml` for in-project
files — that host path is not visible inside the container.

Prefer a context root over binding a host folder at `/opt/projects/<slug>`.
Under `HERMES_TERMINAL_BACKEND=ssh`, Hermes mounts `/opt/projects` read-only,
and Docker cannot create a mount point inside a read-only mount. A nested bind
fails to start unless `$ASSISTANT_DATA_ROOT/projects/<slug>` already exists on
the host. `make doctor` flags a missing one. See
[Extending the stack](extending.md#nested-binds-under-optprojects).

`retrieval: files` (default) means the agent reads `INDEX.md` then opens named
files. `lightrag` and `both` are reserved; the indexer refuses them until ingest
routing exists. Unknown values are also refused.

Context roots are **not** coding roots. They are Hermes-only, read-only, and
never added to `HERMES_WRITE_SAFE_ROOT`. A path already under
`OPENCODE_WORKSPACE_HOST` or `CODING_EXTRA_ROOTS` is visible but writable —
prefer a dedicated context root for notes vaults. See
[OpenCode](opencode.md#coding-roots). `make doctor` warns when `sources.yaml`
lists a host path that is not mounted.

WebUI prefill stale-checks **project-local** INDEX rows only. Extra-root
freshness is `make project-index-check` / `make doctor` on the host.

## How the WebUI brief gets loaded

Lean WebUI chat uses the **gateway** backend. That path does **not** pass the
selected workspace as the agent’s cwd, so Hermes’ native `AGENTS.md` discovery
never runs for browser turns.

Instead, compose wires the stock WebUI hook
`HERMES_WEBUI_PREFILL_MESSAGES_SCRIPT` to
[`compose/hermes/scripts/project-brief-prefill.py`](../compose/hermes/scripts/project-brief-prefill.py).
On each turn the script:

1. Reads `data/hermes/webui/last_workspace.txt` (inside the container:
   `$HERMES_WEBUI_STATE_DIR/last_workspace.txt`).
2. If the workspace is Home (`/opt/projects`) or has no `AGENTS.md`, emits no
   prefill.
3. Otherwise emits the brief as a `system` message (subject to
   `HERMES_WEBUI_PREFILL_CONTEXT_MAX_CHARS`, default 8000).
4. If `INDEX.md` + `.index-manifest.json` exist and look stale **relative to
   files under this project folder**, appends a one-line warning. Extra source
   roots (absolute INDEX paths) are not checked in the WebUI container.

CLI and dashboard sessions can still load `AGENTS.md` natively when the working
directory is the project. Use the same filename so both paths stay in sync.

### Caveats

- `last_workspace.txt` is **global**, not per browser tab. Two tabs on different
  workspaces both see whichever was selected last.
- Oversized briefs are **omitted** (not truncated). Shrink `AGENTS.md` or raise
  the char budget deliberately.
- The prefill script only reads files. Do not point the hook at anything that
  calls a model or the network.
- Custom workspace **names** in `workspaces.json` (e.g. renaming `career` to
  “Job Search”) are preserved across FS discovery. Deleted library folders drop
  from the effective list on the next read even if a stale DB row remains.

## Makefile targets

| Target | Behavior |
|---|---|
| `make project-init PROJECT=…` | Copy `compose/hermes/project-template/` into `data/projects/<slug>/` (refuses if it already exists) |
| `make project-index PROJECT=…` | Rewrite `INDEX.md` and `.index-manifest.json` from `sources.yaml` (or the project tree) |
| `make project-index-check PROJECT=…` | Exit 0 if fresh, 1 if stale or missing |
| `make context-root-add DIR=…` | Mount an absolute host dir into Hermes read-only (`CONTEXT_EXTRA_ROOTS`) |
| `make context-root-list` | Show context roots (and coding roots that already cover a path) |

## When to stay on files vs LightRAG

- **Default:** read `INDEX.md`, open one or two files. Best for small local models.
- **Extra host notes:** declare them in `sources.yaml`, mount with
  `make context-root-add`, re-index. Still file context — not GraphRAG.
- **Large / fuzzy recall:** copy only the **source** half into
  `$ASSISTANT_DATA_ROOT/inputs/<slug>/` and use [Knowledge bases](knowledge-bases.md).
  Never ingest `drafts/`, `applications/`, or other generated trees.
- **Later:** `retrieval: lightrag` on a source will mean “this tree is ingest
  input” for the **hot** LightRAG `WORKSPACE`, not “query many workspaces.”

Projects are **not** auto-ingested.
